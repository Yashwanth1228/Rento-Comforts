# Rento Comforts — Agent Working Rules

## Project status

The JavaScript Next.js App Router foundation and an initial customer-facing visual shell are implemented. No backend, database schema, authentication, or business workflows have been implemented. Read the relevant project documentation before changing related features.

## Required workflow

- Work in small, clearly defined phases. Before a phase, explain its goal and likely affected files in beginner-friendly language.
- Refer to the relevant project documentation before implementing a related feature: [Project brief](docs/PROJECT_BRIEF.md), [Design system](docs/DESIGN_SYSTEM.md), [Planned architecture](docs/ARCHITECTURE.md), and [Implementation plan](docs/IMPLEMENTATION_PLAN.md).
- Do not rebuild working features unnecessarily. Inspect the existing code and behavior before proposing changes.
- Ask for approval before major implementation, dependency installation, or destructive actions.
- Do not invent business policies, prices, reviews, credentials, or claims. Record missing information as unresolved.
- Label requirements **CONFIRMED**, **PROPOSED**, or **UNRESOLVED**; do not imply a proposal has been approved.
- Never call a feature complete without checking its code and behavior against acceptance criteria.
- Use JavaScript, not TypeScript. Do not silently change the planned stack.
- Never hardcode or expose secrets. Use appropriate environment configuration when implementation begins.
- Keep architecture manageable for one developer. Enforce critical inventory, payment, and authorization checks on the backend and keep suitable audit records for critical workflows.
- Use animation thoughtfully and preserve performance, accessibility, and usable reduced-motion behavior.

## Project documentation

Use [Project brief](docs/PROJECT_BRIEF.md) for confirmed scope, proposals, and unresolved decisions; [Design system](docs/DESIGN_SYSTEM.md) for implemented visual conventions and provisional typography; [Architecture](docs/ARCHITECTURE.md) for actual frontend structure and clearly marked future integrations; and [Implementation plan](docs/IMPLEMENTATION_PLAN.md) for verified progress and next prerequisites. Do not claim a planned schema, service, integration, or workflow is implemented until its code and behavior have been verified.
